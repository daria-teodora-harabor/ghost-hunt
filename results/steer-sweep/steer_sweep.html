Steering past the trigger

Each backdoor normally sleeps until it sees its trigger. Can we wake it by hand — adding a direction to the model's activations — so it does the hidden behaviour on prompts that don't contain the trigger? The steering direction is built from one set of prompts and tested on a disjoint held-out set (different words), so these are honest generalisation rates, not in-sample. Diff-in-differences direction (organism minus base, to strip the trigger-prompt confound).

Broad vs. narrow behaviours

Refusal and French steer almost as well as the trigger (0.83–0.96 held-out) — they are broad, low-level features one direction can push. JSON-format and list-position backdoors resist (0.04–0.42): they need a specific structured output a blunt push can't reliably induce.

Held-out, not in-sample

The direction is built on probe carriers and scored on gate carriers — different words. An earlier in-sample number (~75%) overstated it. The floor (no trigger, no steer) is 0.00 everywhere, so any fire is the steering, not leakage.

One caveat on the peak

The "best" layer/alpha is chosen by maximising the held-out rate, which is a mild optimism. A stricter split (choose the setting on a validation set, report on a third) would shave these a little.
